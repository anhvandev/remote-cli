# 24: macOS: `.app`/`.dmg`, launchd, lock screen, login window (view-only)

**What to build:** Replaces `.scratch/remote-cli/issues/31`. Ship `rcli` as an `.app` in a `.dmg`, so TCC grants stick to the bundle. Opening it shows the GUI with Install, and the curl one-liner and `rcli agent install` also work. Install a root LaunchDaemon plus a LaunchAgent limited to the LoginWindow and Aqua sessions. The GUI guides the one-time Screen Recording and Accessibility grants. At the lock screen, capture and input work. At the login window, capture works and input is reported as unavailable (ADR 0001). The Secret Store uses the System Keychain. The build is unsigned, so the guide page covers Gatekeeper. See `.scratch/easy-setup/spec.md`.

**Blocked by:** 23, 14, 17

**Status:** resolved

- [ ] `.dmg` install, the curl one-liner and `rcli agent install` all install both launchd jobs and register the Device; the GUI guides the permission grants
- [ ] Contract suite passes at the lock screen (capture + key)
- [ ] At the login window: Observations work; input Actions fail with a clear 'input unavailable at macOS login window' error
- [ ] Device detail (CLI and Dashboard) shows when a Mac is at the login window
- [ ] Uninstall removes both jobs

## Comments

- 2026-11-10: Implemented on `t/24`. What exists now:
  - `sudo rcli agent install --server <host:port> --key <rk_…> [--name …] [--terminal-user …] [--allow-root]` (`crates/cli/src/macos_install.rs`): puts the app at `/Applications/rcli.app` (copies the bundle it runs from, or builds the same bundle around a bare binary from the curl one-liner and ad-hoc signs it), links `/usr/local/bin/rcli`, writes Device Settings (Terminal User = `SUDO_USER` or `--terminal-user`, `--allow-root` = root always), registers the Device (a wrong key fails here), then writes and bootstraps `/Library/LaunchDaemons/dev.remotecli.agent.plist` (root, `rcli agent run … --session-socket /var/run/rcli/session.sock`, Server Key only in its environment, file mode 0600) and `/Library/LaunchAgents/dev.remotecli.agent.session.plist` (`LimitLoadToSessionType` LoginWindow + Aqua, `rcli agent session`). Prints the Device ID and Device Password.
  - `sudo rcli agent uninstall`: boots out both jobs, deletes both plists, the app, the link, the state directory and the Keychain secrets.
  - Root daemon ↔ session helper (`crates/agent/src/macos_session.rs`): the daemon cannot reach the window server, so displays, capture, input, the AX tree, session state and Lock go to the helper whose session is on the console. With no helper on the console the Device reports `LoginScreen`. Input while the helper is at the login window fails with `input unavailable at macOS login window`. Helpers are accepted only from uid 0 or the owner of `/dev/console`.
  - `MacPlatform::session_state` now also reports `LoginScreen` when `kCGSessionLoginDoneKey` is false (the LoginWindow helper). CLI `rcli device show` (`resources.session: LoginScreen`) and the Dashboard badge ("Màn đăng nhập") already show it.
  - Secret Store: `KeychainSecretStore` (System Keychain) for the root Agent on macOS; it never shows a dialog. A non-root `rcli agent run` keeps the encrypted-file fallback.
  - GUI (macOS): while no Agent answers, an Install form (Server Address, Server Key → admin prompt → `rcli agent install`, then it reopens `/Applications/rcli.app`). The permission guide shows whether Screen Recording / Accessibility are allowed, with **Allow** (system prompts) and buttons that open the matching System Settings panes. A root service opens the GUI in the user's session with `launchctl asuser`.
  - `packaging/macos/build-dmg.sh` builds `target/macos/rcli.app` and `target/macos/rcli-<version>-macos-<arch>.dmg` (GUI build, ad-hoc signed, with an /Applications link).
  - `rcli-contract --session-socket <path>` runs the contract suite the way the installed daemon works.

  **Real-machine acceptance (run on a test Mac, macOS 15, as an admin):**

  1. Build: `packaging/macos/build-dmg.sh` → `target/macos/rcli-0.1.0-macos-aarch64.dmg`. Publish the same binary for the one-liner: `rcli rollout publish target/macos/rcli.app/Contents/MacOS/rcli --version <v> --target macos-aarch64 --key <rollout key file>`, then roll it out.
  2. **.dmg path:** copy the .dmg to the test Mac, open it, drag rcli to Applications (or open it from the .dmg directly). First open: right-click → Open (Gatekeeper; or `xattr -dr com.apple.quarantine /Applications/rcli.app`). The window shows "Agent unreachable" and the Install form: enter the Server Address (host:port of the Agent port) and the Server Key, click Install, authenticate. The installed app reopens. Check: `sudo launchctl print system/dev.remotecli.agent | grep state` → running; `launchctl print gui/$(id -u)/dev.remotecli.agent.session | grep state` → running; the Device appears in the Dashboard with its Device ID; `rcli agent info` shows it connected; `sudo rcli agent password show` works (System Keychain: `sudo security find-generic-password -s dev.remotecli.agent -a device_password /Library/Keychains/System.keychain` lists the item).
  3. In the reopened window click **Allow**, switch rcli on under Screen Recording and Accessibility, quit and reopen: both show "allowed". From a Controller: `rcli shot <id>` shows the desktop; `rcli act <id> …` types into TextEdit.
  4. **Lock screen:** lock (⌃⌘Q). From a Controller: `rcli shot <id>` shows the lock screen, `rcli device show <id>` says `LockScreen`, `rcli unlock <id>` (after `sudo rcli agent unlock-password set` on the Mac) or `rcli act <id> key a` types a dot.
  5. **Login window:** log out. `rcli device show <id>` shows `resources.session: LoginScreen`; the Dashboard shows "Màn đăng nhập"; `rcli shot <id>` shows the login window; `rcli act <id> key a` fails with `input unavailable at macOS login window`. Log in again.
  6. **Reboot:** restart; at the login window the Device comes back Online and is in `LoginScreen`.
  7. **Contract suite at the lock screen and login window:** on the Mac, `sudo launchctl bootout system/dev.remotecli.agent`, then from an SSH session: `sudo ./rcli-contract --session-socket /var/run/rcli/session.sock | tee contract-macos.md` (build it with `cargo build --release -p rcli-agent --bin rcli-contract`), and follow the `NOW:` lines at the Mac. Paste the table here, then `sudo launchctl bootstrap system /Library/LaunchDaemons/dev.remotecli.agent.plist`.
  8. **curl one-liner:** on a clean Mac (or after uninstall): `curl -fsSL https://<dashboard>/install.sh | sudo sh -s -- --key <key>`; same checks as step 2; the Terminal User is the account that ran sudo. Also `sudo /path/to/rcli agent install --server … --key …` directly.
  9. **Uninstall:** `sudo rcli agent uninstall`. Check: both `launchctl print` commands above fail ("could not find service"), `/Library/LaunchDaemons/dev.remotecli.agent.plist`, `/Library/LaunchAgents/dev.remotecli.agent.session.plist`, `/Applications/rcli.app` and `/Library/Application Support/rcli` are gone, and the Keychain item is gone. Delete the Device on the Server by hand (see below). Remove the Screen Recording/Accessibility entries in System Settings if wanted.

  **Shortcuts taken:**
  - Uninstall does not remove the Device from the Server: there is no Agent self-removal message yet (ticket 16 adds it for every OS). An Admin deletes it with `rcli device delete <id>`.
  - The Dashboard's "rcli.dmg" download still serves the raw rolled-out binary (rollouts carry binaries only). The .dmg is built by `packaging/macos/build-dmg.sh` and handed out by hand. The raw binary also works: run it with no arguments for the GUI Install form, which builds the same app bundle.
  - Unsigned builds: TCC grants and the Keychain items' ACL trust the binary's hash, so after `rcli upgrade` / a rolled-out update the grants need to be given again, and reading the Device Password / unlock password fails until they are set again (`sudo rcli agent password set`, `… unlock-password set`). Signing (out of scope) fixes both.
  - The session helper is chosen per call: the first connected helper whose session is on the console (fast user switching is untested). Frames travel over the local socket as raw RGBA (about 60 MB for a 5K display), fine for Observations, maybe slow for Live View on very large displays.
  - `rcli agent server set` is still not persisted across a restart (as before); the daemon restarts with the `--server` from its plist.
  - `--name` defaults to `hostname -s`. The Linux cross-check could not be run here (no Linux C toolchain for `ring`); the non-macOS branches are cfg-gated stubs that bail.

- final code-review fix (S4): macOS install now records the Terminal User through the shared `install.rs` helper: `--terminal-user`, else the account that ran `sudo` (the same rule Linux used). Before, a reinstall without the flag left whatever `settings.json` already had. The GUI install form always passes the flag, so it is unchanged; plists and launchd calls are untouched.
